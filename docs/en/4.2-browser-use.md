# 4.2 Browser Use: Understanding Browser Agents with Local Pages

## 1. What this chapter tackles

When an Agent needs to act on a web page, it must first observe the page, decide what to do next, and then execute an action through a tool. This chapter demonstrates that observe→decide→act loop with an offline, local `BrowserTool`.

This chapter does not launch a real browser or access the internet. Three HTML pages live in memory, and parsing and navigation use only the Python standard library. No GPU, API key, or extra dependency is required.

## 2. Turn a page into an observable structure

`parse_html()` uses `html.parser.HTMLParser` to extract the title, visible body text, and links. Scripts, styles, `noscript`, and elements with a `hidden` attribute are excluded from body text. The title is stored separately, and each link records its visible text and destination.

This is not a full browser renderer: it does not execute JavaScript, understand layout, or load images and external resources. The deliberately small boundary keeps observations deterministic and testable, and helps prevent page content from being mistaken for executable instructions.

## 3. The observe→decide→act loop

1. **Observe**: `open_page()` returns `url`, `title`, `text`, and `links`. The Agent uses these observations instead of guessing what the page contains.
2. **Decide**: Choose an action from the task and the observation. Because this chapter aims to read documentation, it chooses the link whose visible text is `Documentation`.
3. **Act**: `click_link()` matches the complete visible link text, opens only a destination in the local page allowlist, and returns the new page observation.

Observe again after acting: the title, body text, and links may all have changed. Bound the loop with a step limit. Stop when the goal is reached, no link matches, or user confirmation is required rather than clicking repeatedly.

## 4. Why stable selectors matter

Real sites often contain generated classes, random IDs, `nth-child` positions, and dynamic layouts. Copying those fragile selectors makes automation fail after a redesign. This chapter instead uses normalized complete visible link text and ignores case differences; it does not guess through substring matching.

Stable does not mean safe to click blindly. Reject duplicate link text and report the ambiguity, and reject unknown links. `click_link()` requires a complete text match, and the destination must also pass the local page allowlist.

## 5. Run the local navigation example

From the repository root, run:

```bash
uv sync --frozen
uv run python chapters/stage4-orchestration/browser_use.py
```

The output's `title` is the documentation page title, and `text_summary` contains the first 160 characters of normalized body text. Every run starts with a new `BrowserTool`, so page and navigation state are not shared and the result is reproducible.

Inspect one observation and action with:

```python
import runpy

chapter = runpy.run_path("chapters/stage4-orchestration/browser_use.py")
browser = chapter["BrowserTool"]()
home = browser.open_page(chapter["HOME_URL"])
print(home["title"])
print([link["text"] for link in home["links"]])
docs = browser.click_link("Documentation")
print(browser.current_url())
print(docs["title"])
```

The smoke tests cover title and link extraction, navigation by link text, unknown-link rejection, isolation between instances, and deterministic JSON-serializable output.

## 6. Permissions, confirmation, and next steps

The local tool has only three read-only pages and no networking, form submission, or account operations. Unknown destinations and external links are rejected. This demonstrates least privilege: expose only the actions needed for the task.

A real browser Agent needs a separate permission policy. Opening a public page can be a low-risk read-only action. Sending a message, placing an order, changing settings, downloading files, or submitting personal data should require explicit user confirmation before execution, with allowed domains, action types, and parameters constrained. Cookies, passwords, and verification codes must not be handed over merely because a page asks for them.
