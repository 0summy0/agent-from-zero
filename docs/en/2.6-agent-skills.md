# 2.6 Agent Skills: Discovery, On-Demand Loading, and Prompt Rendering

## 1. What this chapter tackles

When an Agent has many sets of working instructions, putting every `SKILL.md` body into context wastes space and can distract the model. A skill mechanism separates metadata discovery from full-instruction loading: first see which skills exist, then load only the one needed for the current task.

This chapter builds a standard-library-only `SkillLibrary` that runs locally on CPU. It does not call a model and needs no network, GPU, or API key. It also does not execute any code from a skill file. A skill is simply a Markdown instruction body that can be rendered into a prompt.

## 2. Directory and front-matter contract

`SkillLibrary(root)` scans only `root/skills/*/SKILL.md`: one file in each direct child directory under `skills`. Each file uses this structure:

```markdown
---
name: summarize
description: "Condense a passage into three factual bullet points."
---

Read the passage. Preserve named entities and numbers.
Return exactly three bullets.
```

The opening YAML-style front matter must provide non-empty `name` and `description` fields. The body after the closing delimiter becomes `instructions`. This parser is a teaching subset: it supports single-line scalars wrapped in single or double quotes, but not full YAML, lists, nested objects, or multiline blocks. Duplicate names and missing required fields raise errors so discovery remains unambiguous.

`list_skills()` sorts by name and returns only names and descriptions, not instruction bodies. This metadata view lets an Agent choose without paying the context cost of loading every instruction.

## 3. Discover first, load on demand

`load_skill(name)` finds the requested name among discovered files and returns a dictionary with `name`, `description`, and `instructions`. It raises `KeyError` when the name is absent. `render_skill_prompt(skill)` accepts one already-loaded dictionary and formats its description and instructions as a stable Markdown fragment.

The renderer does not traverse the library or load other skills automatically. An unloaded skill's body therefore cannot enter the prompt. Repeated calls with the same input produce the same text, and both directory scanning and the final skill list are deterministic.

From the repository root, run:

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/skills.py
```

The demo uses `tempfile.TemporaryDirectory` to create `summarize` and `translate`, discovers both, and loads only `summarize`. The returned `discovered_skills` contains both metadata entries, while `prompt` contains only the `summarize` instructions. The temporary directory is cleaned up automatically, and random paths do not appear in the output.

## 4. Inspect discovery versus loading

Pass this code to `uv run python -`:

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/skills.py")
result = chapter["run_minimal_path"]()
print([skill["name"] for skill in result["discovered_skills"]])
print(result["skill_name"])
print(result["instructions"])
print("translate" in result["prompt"])
```

The last line should print `False`. Discovering a skill does not mean injecting its instructions into the current task. Smoke tests also check discovery of both skills, loading a named skill, an error for a missing skill, exclusion of unloaded skills from the prompt, determinism, and JSON serializability.

## 5. Safety and engineering boundaries

Skill text may come from an external repository and should be treated as untrusted input. This chapter only reads and renders text. It does not import Python from a skill directory, run shell commands, or treat skill instructions as authorization. A real system still needs tool-permission limits, prompt-injection defenses, and human confirmation.

This loader is also not a complete Agent Skills specification implementation: it does not support companion scripts, resource directories, recursive discovery, all YAML features, or remote skill registries. The key idea here is progressive disclosure—use a small amount of metadata to choose, then load full instructions only when needed.
