# 2.5 A Minimal MCP Subset: Calling Tools with JSON-RPC over stdio

## 1. What this chapter tackles

Agents need a uniform way to discover and call external tools. MCP organizes tool descriptions, arguments, and results into protocol messages so a host and a tool server do not need a custom interface for every tool.

This chapter implements a **teaching-only MCP subset, not a complete MCP SDK**. It covers only JSON-RPC 2.0 over stdio, initialization, `tools/list`, `tools/call`, and one `add` tool. It does not implement resources, prompts, sampling, roots, authentication, HTTP/SSE, or full SDK lifecycle management. The code uses only the standard library, runs locally on CPU, and needs no network, GPU, or API key.

## 2. One JSON message per line

The server and client use subprocess pipes: the client writes to the server's stdin and reads its stdout. Each message is one JSON object followed by a newline, called newline-delimited JSON. Logs must not go to stdout because they would corrupt the protocol stream.

A JSON-RPC request contains `jsonrpc: "2.0"`, an integer `id`, a `method`, and optional `params`. A response reuses the same `id` and contains either `result` or `error`. A notification has no `id`, and the server does not reply to it.

The minimal sequence is:

1. The client sends `initialize` to negotiate the protocol version and capabilities.
2. The client sends a `notifications/initialized` notification.
3. The client sends `tools/list` and receives tool names and JSON Schemas.
4. The client sends `tools/call` with a tool name and arguments.
5. The client closes stdin; the server reaches EOF and exits normally.

A successful `tools/call` result uses MCP's `content` array. Here the text content is `{"type": "text", "text": "42"}`, and `isError: false` marks a successful tool call. An unknown method returns a JSON-RPC error with code `-32601`.

## 3. Run the client and server

From the repository root, run:

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/mcp_minimal.py
```

The output contains the initialization result, tool list, result of `add(17, 25)`, `closed_normally: true`, and `server_exit_code: 0`. The client uses `subprocess.Popen` to start the same file in `--server` mode, so no separate server file or MCP package is needed.

You can also start the server alone and write JSON requests to it one line at a time. End input with Ctrl-D, or Ctrl-Z followed by Enter in a Windows terminal:

```bash
uv run python chapters/stage2-agent-core/mcp_minimal.py --server
```

## 4. See how a request becomes a result

`handle_request()` dispatches by method name. `initialize` returns the protocol version, `tools` capability, and server information. `tools/list` returns the `add` input schema. `tools/call` checks the tool name and verifies that `a` and `b` are finite numbers. Booleans are not accepted as numbers, and a sum that overflows to infinity is rejected.

Inspect the same dispatcher without starting a subprocess:

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/mcp_minimal.py")
request = {
    "jsonrpc": "2.0",
    "id": 7,
    "method": "tools/call",
    "params": {"name": "add", "arguments": {"a": 17, "b": 25}},
}
print(chapter["handle_request"](request))
```

`MCPClient.request()` assigns increasing ids and waits for the response with the matching id. `close()` closes stdin first and waits for the server to exit, escalating to termination or killing only after a timeout. Smoke tests check initialization, tool listing, `add`, an unknown-method error, and process exit code 0.

## 5. Boundaries of this subset

Real MCP includes more capability negotiation, notifications, error conventions, cancellation, progress, authentication, and transports. This chapter fixes the protocol version at `2024-11-05`, exposes one side-effect-free tool, and waits synchronously for each response. It is useful for understanding the message flow but should not be used as a production SDK.

Do not confuse the subprocess exit code with a tool execution result: `server_exit_code` describes the server process, while `isError` describes one tool call. A JSON-RPC error means the request itself was not handled successfully by a method.

Pass this code to `uv run python -`:

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/mcp_minimal.py")
result = chapter["run_minimal_path"]()
print(result["initialize"]["result"]["serverInfo"])
print(result["tools"]["result"]["tools"][0]["name"])
print(result["add_call"]["result"]["content"][0]["text"])

```
