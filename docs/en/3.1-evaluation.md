# 3.1 Evaluation: Measuring Answer Quality with a Tiny Dataset

## 1. What this chapter tackles

An Agent that can answer a question is not necessarily reliable. Evaluation turns “looks good” into a repeatable check: fix the inputs, expected answers, and decision rules, then count how many answers pass.

This chapter uses four toy text questions without model calls or external services. The focus is the evaluation workflow, not the difficulty of the questions.

## 2. Three basic checks

`normalize_text()` folds case and collapses extra whitespace. `exact_match()` requires the normalized answer to equal the expected answer or an allowed alias, so `PARIS`, `Paris`, and ` four ` can all be accepted by the rules.

`contains_expected()` only checks whether the expected answer appears in the prediction. It is more permissive and accepts “The answer is Paris,” but it can also falsely accept a wrong sentence containing the target term. Use it as a separate diagnostic signal.

`evaluate()` takes a dataset and one answer per item, then returns the total, pass count, pass rate, and per-item results. An empty dataset raises an error instead of producing a meaningless pass rate.

## 3. Run the minimal evaluation

From the repository root, run:

```bash
uv run python chapters/stage3-reliability/evaluation.py
```

Of the four questions, `paris` passes after case normalization, `SEVEN` passes through the alias `seven`, and `blue` fails, so `pass_rate` is 0.75. The per-item `results` retain predictions to help locate the source of failures.

## 4. Accuracy is not everything

Accuracy or pass rate answers “how many items met a predefined standard,” but release decisions should also examine at least these measures:

- Task success rate: whether a multi-step task actually achieved its goal, not merely whether its final text matched.
- Evidence citation: whether claims have reliable support, citations substantiate them, and sources can be checked.
- Latency: how long users wait and whether tail latency is acceptable.
- Cost: how many tokens, tool credits, or currency units one task and a batch evaluation consume.

Also inspect failure categories, performance across difficulties and languages, exception rates, and safety. One aggregate accuracy can hide severe failures in a few critical scenarios.

## 5. Inspect the result

Pass this code to `uv run python -`:

```python
import runpy

chapter = runpy.run_path("chapters/stage3-reliability/evaluation.py")
print(chapter["run_minimal_path"]()["pass_rate"])
print(chapter["contains_expected"]("The answer is PARIS.", "paris"))
report = chapter["evaluate"](chapter["EVALUATION_SET"], ["4", "Paris", "green", "7"])
print(report["passed"])
```

The smoke tests cover exact matching, aliases, case normalization, failures, empty-dataset errors, answer-count validation, and determinism. After changing a toy answer, use the per-item report to distinguish a rule problem from an answer problem.
