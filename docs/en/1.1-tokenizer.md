# 1.1 Tokenizer: See How a Model Splits Chinese Text

## 1. What this chapter tackles

A language model does not read the characters and words we see; it reads token IDs. In this chapter, we will not train a model or download model weights. We will use only the `tokenizer.json` file from Qwen2.5-0.5B-Instruct to encode a Chinese sentence and its English counterpart. A CPU Python environment is enough. The first run downloads roughly 6.8 MB of tokenizer data, and no API key is required.

## 2. What a token really is

A token is a unit of text produced from a tokenizer's vocabulary. It can be a common word, one character, part of a word, or an English fragment that includes a leading space. Avoid rules such as “one Chinese character always equals one token” or “one English word always equals one token.” A different vocabulary can produce a different split.

A context window is measured in tokens, not in the character or word counts we normally use. When the same meaning is split into more pieces, it generally occupies more context positions and may cost more to process. Token count alone, however, does not tell us whether an answer is good.

## 3. Run the first experiment

From the repository root, run the following two commands. The first installs the locked dependencies, and the second loads the tokenizer and encodes the Chinese and English samples:

```bash
uv sync --frozen
HF_ENDPOINT=https://hf-mirror.com uv run python chapters/stage1-how-lm-works/tokenizer.py
```

The program first tries the Hugging Face endpoint selected by `HF_ENDPOINT`. On this execution machine, the mirror returned HTTP 403, so the module also includes a ModelScope URL for the same Qwen tokenizer as a fallback. `TOKENIZER_URL` can override the download location explicitly. The file is cached after the first download. This experiment loads only the tokenizer, not the 0.5B model weights, and does not require PyTorch.

## 4. Read the resulting split

These are the measured results from one Qwen tokenizer. The leading spaces in the English fragments matter because they encode information about text boundaries.

| Sample | Characters | Readable token fragments | Tokens |
|---|---:|---|---:|
| Chinese: `智能体现在会调用工具` | 10 | `智能`, `体现在`, `会`, `调`, `用`, `工具` | 6 |
| English: `Agents can call tools now` | 25 | `Agents`, ` can`, ` call`, ` tools`, ` now` | 5 |

The Chinese word for “call,” `调用`, is split into `调` and `用`, while `智能` and `工具` remain intact. This is what fragmented Chinese text looks like in practice: some common sequences are merged, while other natural-looking words are split. The Chinese sample uses one more token than the English sample here, but that does not mean all Chinese text requires more tokens. Different text or a different tokenizer can change the ratio.

## 5. Inspect the returned structure

From the repository root, pass this Python code to `uv run python -` or run it line by line in a Python REPL. `runpy.run_path` loads the chapter module from a directory containing hyphens. The returned dictionary follows the same minimal path used by the smoke test.

```python
import runpy

chapter = runpy.run_path("chapters/stage1-how-lm-works/tokenizer.py")
result = chapter["run_minimal_path"]()
print(result["chinese"]["tokens"])
print(result["chinese"]["token_count"])
print(result["english"]["tokens"])
print(result["english"]["token_count"])
```

The test does not hard-code one exact sequence of token strings. Instead, it checks fields such as `chapter`, `model`, `chinese`, and `english`, verifies their types, and confirms that token counts match the lengths of the ID lists. This detects broken result contracts while allowing reasonable tokenizer implementation differences.
