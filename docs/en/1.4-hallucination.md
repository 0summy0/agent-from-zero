# 1.4 Hallucination: Why Models Invent Answers

## 1. What this chapter tackles

Language models sometimes give plausible-sounding answers that have no basis in fact. This is called hallucination. Without model weights or an online service, this chapter builds a minimal “answer only with evidence” mechanism: retrieve from a local knowledge base first, then decide whether to answer or abstain.

Everything uses only the Python standard library. No network, GPU, or API key is required. The toy knowledge base is intentionally tiny so the control flow stays visible; it is not a demonstration of knowledge-base quality.

## 2. Hallucination is not lying

Lying means knowingly deceiving someone; hallucination usually has no such intent. A language model is optimized to produce plausible continuations of its context. Language patterns, factual associations, and reasoning habits learned during training are mixed together. When evidence is missing, a question is ambiguous, or context conflicts, the model may still generate a fluent guess.

Lowering temperature, sounding more confident, or writing a longer answer therefore does not establish truth. Sampling in Chapter 1.2 changes which token is selected; it does not supply factual evidence.

## 3. A minimal answer-only-with-evidence mechanism

This chapter separates answering into three steps:

1. **Retrieve**: lowercase the question, remove function words such as `what`, `is`, and `the`, then search each fact's title, aliases, and text.
2. **Gate on evidence**: allow an answer only when one record covers every content keyword in the question. Prefer records with more matches in their title or aliases.
3. **Answer or abstain**: quote the evidence text and include its ID when supported; otherwise say that the system does not know and needs more information instead of inventing an answer.

`answer_with_evidence(question, knowledge_base)` returns `status`, `answer`, `evidence`, and `query_keywords`. A `grounded` status means the evidence-answering path was used; `abstain` means the system declined to answer.

The gate is deliberately conservative. For example, “What is the capital of France and Canada?” needs two facts, and this chapter will not stitch two isolated facts into an answer. Keyword coverage is also not logical entailment: it does not handle negation, complex comparisons, or paraphrases. Real systems need more reliable retrieval, evidence validation, and constrained generation.

## 4. Run the comparison experiment

From the repository root, run:

```bash
uv sync --frozen
uv run python chapters/stage1-how-lm-works/hallucination.py
```

The minimal path compares two questions. The in-knowledge-base question about France's capital returns `Paris is the capital of France.` with evidence `kb-capital-france`. The out-of-knowledge-base question about Atlantis's capital abstains because no local evidence covers `atlantis`.

The grounded answer is quoted directly from evidence rather than generated freely. This keeps retrieval failures separate from language-generation choices.

## 5. Inspect the result

Pass this code to `uv run python -`:

```python
import runpy

chapter = runpy.run_path("chapters/stage1-how-lm-works/hallucination.py")
result = chapter["run_minimal_path"]()
print(result["grounded_case"]["status"])
print(result["grounded_case"]["answer"])
print(result["abstention_case"]["status"])
print(result["abstention_case"]["answer"])
```

With evidence, the output shows `grounded` and a citation with an ID. Without evidence, it shows `abstain` and an explicit statement of not knowing. The smoke tests also check that evidence IDs are non-empty, a combined question is not incorrectly stitched together, and repeated runs are identical.

## 6. Limits, self-check, and next step

Retrieval, citations, and abstention are engineering mitigations, not a complete elimination of hallucination. A knowledge base can be stale or incomplete, retrieval can miss evidence, and a generator can ignore evidence. Stronger guarantees require evaluating whether citations really support claims and adding human review for high-stakes uses.
