# 2.3 The ReAct Loop: How Thought, Action, and Observation Drive an Agent

## 1. What this chapter tackles

An agent does more than generate one answer: it can act on feedback and keep going. This chapter implements a tiny ReAct loop by hand. Each step produces a Thought, selects an Action, executes a tool, records the Observation in the trace, and then decides what to do next.

The example needs both arithmetic and a city lookup, so it must call two local tools. No network, GPU, model weights, or API key is required.

## 2. What Thought, Action, and Observation mean

- Thought: a brief judgment about the goal and earlier observations, not hidden reasoning.
- Action: a structured tool call with a tool name and input arguments.
- Observation: the actual tool result; the loop uses it to plan the next step.

`deterministic_planner()` uses fixed rules to recognize an arithmetic expression and a city name, then checks the trace for successful observations. It neither calls a model nor chooses the next step randomly.

## 3. Run a loop that needs tools

From the repository root, run:

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/react_loop.py
```

The default question calls `calculator` and then `lookup_city`, before selecting `finish`. The calculator interprets numbers, parentheses, addition, subtraction, multiplication, division, and unary signs without `eval()`. City lookup only reads a local dictionary.

Print the full trace:

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/react_loop.py")
result = chapter["run_minimal_path"]()
for step in result["trace"]:
    print(step["step"], step["thought"])
    print("Action:", step["action"])
    print("Observation:", step["observation"])
print(result["answer"])
```

The final answer is `Calculation result: 1152. Shanghai is in China.` The final `finish` record has no tool observation because it does not call an external tool.

## 4. Why max_steps is mandatory

A tool may fail, and a planner may repeatedly select the same action. `max_steps` is a hard safety boundary: once reached, the loop returns `stop_reason="max_steps"` without making more tool calls.

An unknown request takes a safe finish branch. When a known tool receives unsupported input, it returns `ok=False`, and the loop stops with `tool_error`. This prevents the toy agent from looping forever when it cannot complete the task.

## 5. Real LLM agents use this same loop

A real LLM agent has the same outer Thought → Action → Observation loop. The main difference is that its planner is usually a model: the model generates the next action from the goal, tool descriptions, and earlier observations. Outer code still executes tools, records results, limits steps, and stops on failure or timeout.

The deterministic planner replaces the model so every trace is reproducible and testable, separating agent control flow from model capability. Using rules here does not mean real agents must use rules.

## 6. Inspect the boundaries yourself

Replace `run_minimal_path()` with `run_react_loop("Calculate 20 + 22", max_steps=1)` to see how the step limit prevents a final answer. Then ask an unsupported question and inspect the `finish` action.
