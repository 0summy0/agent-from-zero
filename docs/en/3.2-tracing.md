# 3.2 Tracing: Debugging Agents with a JSONL Call Chain

## 1. What this chapter tackles

When an Agent fails, the final error log is usually not enough. You need to know what happened earlier, which tool was slow, and where in the call chain the failure occurred.

This chapter implements a tiny tracer that records one toy Agent run through four nested or related spans. Everything is written to a local JSONL file without network access, a GPU, or an API.

## 2. Trace versus log

A log usually contains discrete events in arrival order, such as “query started” and “query finished.” A trace expresses causality through `span_id` and `parent_span_id`, organizing planning, tool calls, and answering into a tree for one task.

Each span records a name, start and end times, millisecond duration, and attributes. Several spans can share a parent, so a call chain can branch rather than forming one simple sequence.

`TraceWriter.span()` is a context manager: a normal exit writes `ok`, while an exception writes `error` and the error message before propagating upward. Duration is end minus start and is clamped to a non-negative value.

## 3. Run the minimal trace

From the repository root, run:

```bash
uv run python chapters/stage3-reliability/tracing.py
```

`run_minimal_path()` creates `trace.jsonl` in a temporary directory, runs four fixed steps, and returns the span count and key spans. The temporary directory is cleaned up automatically; the returned value is a serializable summary.

Key spans include `agent.run`, `tool.lookup`, and `agent.answer`; the full file also contains `agent.plan`. A fixed clock makes the example's timestamps and durations repeatable.

## 4. Why Agent debugging needs the full call chain

Suppose the final answer is wrong. A complete trace helps distinguish bad step planning, incorrect tool data, a model misreading tool output, and a mistake during answer synthesis.

A parent span's duration includes its children's durations, so you can follow the tree to locate bottlenecks. Exception attributes preserve the failing layer instead of exposing only the outermost error. For cross-process tracing, correlation IDs can also be written alongside logs.

For privacy, do not put secrets, sensitive user data, or unnecessarily large tool outputs into attributes. A production system also needs sampling, retention policies, and access control.

## 5. Inspect the call chain

Pass this code to `uv run python -`:

```python
import json
import runpy
import tempfile
from pathlib import Path

chapter = runpy.run_path("chapters/stage3-reliability/tracing.py")
with tempfile.TemporaryDirectory() as directory:
    result = chapter["ToyAgentRunner"](directory, clock=lambda: 1.0).run("What is 2 + 2?")
    path = Path(directory) / "trace.jsonl"
    records = [json.loads(line) for line in path.read_text(encoding="utf-8").splitlines()]
print(result["span_count"])
print([(record["name"], record["parent_span_id"]) for record in records])
```

The smoke tests cover parent-child relationships, non-negative durations, line-by-line JSONL parsing, exception span recording, temporary-directory output, and determinism with a fixed clock. Fake clocks avoid real waiting in tests.
