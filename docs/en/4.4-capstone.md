# 4.4 Capstone: Local Research Desk

## 1. What this project tackles

Local Research Desk combines earlier chapters into a runnable, inspectable research flow: accept a question, scan for injection attempts, produce a structured plan, execute local tools, cite evidence, and finally answer or abstain. It uses only the Python standard library and the repository's existing `jsonschema`. It runs on CPU without network access, a GPU, model weights, or a paid API.

**This is a teaching capstone, not a production system.** The planner uses fixed rules instead of an LLM, the knowledge base contains only a few hand-written facts, and retrieval relies on keyword coverage. It demonstrates agent control flow and reliability boundaries; it is not an open-domain research capability.

## 2. One pipeline, several reliability mechanisms

Each `run(question)` passes through these stages:

1. **Input checks and safety scanning**: bound the question length, normalize Unicode with NFKC, and match known prompt-injection patterns. A match is rejected before any tool runs.
2. **Task recognition**: fixed rules identify arithmetic, city lookup, and knowledge-base requests, then produce a plan with `action`, `arguments`, and `confidence`.
3. **Schema validation**: every plan passes `PLAN_SCHEMA`, which constrains tool arguments, action names, extra fields, and the number of final evidence IDs.
4. **A bounded ReAct loop**: execute Thought → Action → Observation for at most 4 steps, including the final `finish`.
5. **Evidence gating and answering**: quote local records for knowledge answers; calculation and city observations also become citable evidence. Return `abstain` when no supporting evidence exists.
6. **Memory, tracing, and evaluation**: keep a recent-message window and a summary of older messages, write a JSONL trace, and report token estimates, tool-call counts, and small metrics.

The result includes `answer`, `status`, `evidence`, `trace`, `usage`, `evaluation`, `memory`, `security`, `plan_validation`, and `trace_file`. Every value can be serialized with `json.dumps(..., allow_nan=False)`.

## 3. Run the demo and a single question

From the repository root, run:

```bash
uv run python -m agent_from_zero.capstone --demo
```

The demo runs two fixed questions. France's capital is inside the knowledge base and returns `grounded`; Atlantis's capital has no local evidence and returns `abstain`. The top-level `statuses` is `["grounded", "abstain"]`, with complete results under `cases.grounded` and `cases.abstain`.

Research one question:

```bash
uv run python -m agent_from_zero.capstone "What is the capital of France?"
```

You can also write the trace to a directory of your own:

```bash
uv run python -m agent_from_zero.capstone "Calculate (6 + 2) * 7" --trace-dir traces/research
```

This writes one JSON object per line to `traces/research/trace.jsonl`. Without `--trace-dir`, each run creates a separate temporary directory. The result marks `temporary: true` without exposing the random path, so the default result remains deterministic. When a directory is supplied to the demo, traces go into its `grounded` and `abstain` subdirectories.

## 4. Inspect grounded answers and abstention

A grounded result quotes the evidence directly and includes its ID in brackets:

```text
Paris is the capital of France. [kb-capital-france]
```

A no-evidence result does not invent a plausible capital; it abstains explicitly:

```text
I don't know; no verifiable local evidence is available for this question.
```

`retrieve_knowledge()` requires one record to cover every content keyword in the question. Therefore, “What are the capitals of France and Canada?” is not assembled from two isolated facts. The rule is deliberately conservative: it does not understand negation, complex comparisons, or every paraphrase, and keyword coverage is not logical entailment.

## 5. Structured plans and the four-step ReAct loop

`calculator`, `lookup_city`, and `search_knowledge` are the only three local tools. A plan must pass JSON Schema before entering `execute_action()`. Booleans cannot masquerade as confidence values, and unknown actions, extra arguments, and a `grounded` final plan without evidence are rejected.

The loop executes at most 4 steps. A question that calculates first and then looks up Shanghai selects `calculator`, `lookup_city`, and `finish`. A tool failure enters the abstention branch instead of retrying repeatedly. Safety rejection happens before planning and records only one `reject` observation.

Inspect a plan and its trace directly:

```python
import json
from agent_from_zero.capstone import run, validate_plan

result = run("Calculate (128 + 256) * 3, then look up the country of Shanghai.")
for step in result["trace"]:
    print(step["step"], step["thought"])
    print(step["action"]["action"], step["action"]["arguments"])
print(result["answer"])
print(json.dumps(result["evaluation"], sort_keys=True))

plan = {"action": "calculator", "arguments": {"expression": "2 + 2"}, "confidence": 0.9}
print(validate_plan(plan))
```

The final answer includes `1152`, Shanghai's country `China`, and two citations. The rule planner depends only on the question and earlier observations, not random sampling, so identical input produces the same trace and answer.

## 6. Memory, context, and the JSONL trace

`ContextMemory` keeps at most 4 recent messages. Content that slides out of the window enters a lossy summary, and the complete context is then trimmed to 640 characters. The `memory` field reports the summary, recent messages, eviction count, context character count, and estimated tokens.

There is no model in this project, so the summary is never treated as a new fact. It demonstrates context organization; the final answer depends only on validated tool observations and evidence records. A real model-backed system would also need checks for lost constraints and errors introduced by summarization.

Each ReAct step and the final result are written as separate JSONL lines. Read the trace from a user-supplied directory like this:

```python
import json
from pathlib import Path
from agent_from_zero.capstone import run

result = run("What is the capital of France?", trace_dir="traces/research")
path = Path(result["trace_file"]["directory"]) / result["trace_file"]["name"]
records = [json.loads(line) for line in path.read_text(encoding="utf-8").splitlines()]
print(result["trace_file"]["event_count"])
print([record["event"] for record in records])
print(records[-1]["evidence_ids"])
```

The output is the step count plus one, `['step', 'step', 'result']`, and `['kb-capital-france']`. The trace contains no real timing or random timestamps, making it reproducible. Production tracing usually also needs correlation IDs, time, sampling, retention, and access control.

## 7. Safe arithmetic, injection scanning, and evaluation metrics

The calculator parses an expression into an AST and accepts only finite numbers, parentheses, unary signs, and `+`, `-`, `*`, `/`, `//`, `%`. It rejects calls, names, attribute access, powers, oversized numbers, and non-finite results. It never uses `eval()` or `exec()`.

The injection scanner covers only a few known patterns, such as ignoring prior instructions, revealing a system prompt, and calling unauthorized tools. It can miss paraphrased or encoded attacks and can flag benign security discussions, so it is not a complete security boundary. The project also has no shell, file-deletion, network, or paid tool.

Token counts in `usage` use the teaching estimate “normalized characters divided by four”; they are not counts from a real tokenizer. Both `network_calls` and `cost_usd` are zero. `evaluation` reports task success, abstention, injection blocking, evidence count, citation coverage, whether citations appear in the answer, step count, and compliance with the limit. These are small diagnostic metrics, not complete proof of factual correctness.

## 8. Tests, boundaries, and next steps

Run the corresponding smoke tests:

```bash
uv run pytest tests/smoke/test_chapter_4_4_capstone.py
```

The tests cover grounded answers, no-evidence abstention, arithmetic, city and multi-tool questions, injection rejection, JSONL traces, determinism, Schema boundaries, context summaries, and the CLI demo. Answer the three questions in `quizzes/4.4-capstone.en.json`; the Chinese set is `quizzes/4.4-capstone.json`.

This capstone works as a comprehensive course checkpoint but should not be deployed directly. Production systems still need reliable retrieval, current auditable data, evidence-support judgments, human confirmation, permission isolation, rate and resource limits, privacy protection, continuous attack evaluation, and real quality benchmarks. You can replace the rule planner next, but preserve the four-step limit, default denial, evidence gate, and reproducible trace.
