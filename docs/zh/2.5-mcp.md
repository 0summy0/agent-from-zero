# 2.5 MCP 最小子集：用 JSON-RPC over stdio 调用工具

## 1. 这一章要解决什么

Agent 需要一种统一方式发现和调用外部工具。MCP 把工具描述、调用参数和返回结果组织成协议消息，让宿主与工具服务器不必为每个工具单独设计接口。

本章实现一个**教学用 MCP 子集，不是完整 MCP SDK**。它只覆盖 JSON-RPC 2.0 over stdio、初始化握手、`tools/list`、`tools/call` 和一个 `add` 工具；不实现资源、提示词、采样、roots、认证、HTTP/SSE 或完整 SDK 的生命周期管理。代码仅用标准库，在 CPU 上本地运行，不需要网络、GPU 或 API key。

## 2. 一行一个 JSON 消息

服务端和客户端各自使用一个子进程管道：客户端写服务器的 stdin，再读服务器的 stdout。每条消息是一个 JSON 对象加一个换行符，称为 newline-delimited JSON；日志不能写进 stdout，否则会污染协议流。

JSON-RPC 请求包含 `jsonrpc: "2.0"`、整数 `id`、`method` 和可选的 `params`。响应复用同一个 `id`，并包含 `result` 或 `error`。通知没有 `id`，服务端不回复通知。

最小时序如下：

1. 客户端发送 `initialize`，协商协议版本和双方能力。
2. 客户端发送 `notifications/initialized` 通知。
3. 客户端发送 `tools/list`，得到工具名称和 JSON Schema。
4. 客户端发送 `tools/call`，传入工具名与参数。
5. 客户端关闭 stdin，服务端读到 EOF 后正常退出。

`tools/call` 的成功结果使用 MCP 的 `content` 数组。本章的文本内容为 `{"type": "text", "text": "42"}`，并用 `isError: false` 表示工具调用成功。未知方法返回 JSON-RPC error，错误码为 `-32601`。

## 3. 跑通客户端与服务器

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/mcp_minimal.py
```

输出包含握手结果、工具列表、`add(17, 25)` 的调用结果，以及 `closed_normally: true` 和 `server_exit_code: 0`。客户端通过 `subprocess.Popen` 启动同一文件的 `--server` 模式，所以不需要另建服务器文件或安装 MCP 包。

也可以单独启动服务器，向它逐行写入 JSON 请求；输入结束后按 Ctrl-D，或在 Windows 终端按 Ctrl-Z 后回车：

```bash
uv run python chapters/stage2-agent-core/mcp_minimal.py --server
```

## 4. 观察请求怎样变成结果

`handle_request()` 按方法名分派请求。`initialize` 返回协议版本、`tools` 能力和服务器信息；`tools/list` 返回 `add` 的输入 schema；`tools/call` 先检查工具名，再验证 `a`、`b` 都是有限数字。布尔值不会被当作数字，和值溢出为无穷大时也会拒绝。

下面不启动子进程，直接检查同一个分派函数：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/mcp_minimal.py")
request = {
    "jsonrpc": "2.0",
    "id": 7,
    "method": "tools/call",
    "params": {"name": "add", "arguments": {"a": 17, "b": 25}},
}
print(chapter["handle_request"](request))
```

`MCPClient.request()` 自动分配递增 id，并等待具有相同 id 的响应。`close()` 先关闭 stdin，再等待服务器退出；只有超时后才升级为终止或杀死进程。冒烟测试会检查握手、列工具、调用 `add`、未知方法的 error 和进程退出码 0。

## 5. 这个子集的边界

真实 MCP 还包括更多能力协商、通知、错误约定、取消、进度、认证和传输实现。本章固定使用 `2024-11-05` 协议版本，只提供一个无副作用工具，并用同步请求等待响应；它适合用来理解消息流，不应直接作为生产 SDK 使用。

尤其不要把子进程退出码与工具执行结果混淆：`server_exit_code` 描述服务器进程，`isError` 描述一次工具调用。JSON-RPC error 则表示请求本身没有被方法成功处理。

## 6. 亲手检查结果

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/mcp_minimal.py")
result = chapter["run_minimal_path"]()
print(result["initialize"]["result"]["serverInfo"])
print(result["tools"]["result"]["tools"][0]["name"])
print(result["add_call"]["result"]["content"][0]["text"])
print(result["server_exit_code"])
```
