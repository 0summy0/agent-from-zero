# 2.3 ReAct 循环：思考、行动与观察如何驱动 Agent

## 1. 这一章要解决什么

Agent 不是只生成一段回答，而是可以根据环境反馈继续行动。本章手写一个极简 ReAct 循环：每一步先产生 Thought，再选择 Action，执行工具后把 Observation 写回 trace，然后决定下一步。

示例问题同时需要算术和城市查询，因此必须调用两个本地工具。全程不需要网络、GPU、模型权重或 API key。

## 2. Thought、Action、Observation 是什么

- Thought：对当前目标和已有观察的简短判断，不是隐藏推理过程。
- Action：结构化工具调用，包含工具名和输入参数。
- Observation：工具实际返回的结果；循环只能根据这个结果继续规划。

`deterministic_planner()` 用固定规则识别算术表达式和城市名，再检查 trace 中是否已有成功观察。它不会调用模型，也不会随机决定下一步。

## 3. 跑通一个需要工具的循环

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/react_loop.py
```

默认问题会依次调用 `calculator` 和 `lookup_city`，最后选择 `finish`。计算器只解释数字、括号、加减乘除和一元正负号，不使用 `eval()`；城市查询只读取本地字典。

打印完整 trace：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/react_loop.py")
result = chapter["run_minimal_path"]()
for step in result["trace"]:
    print(step["step"], step["thought"])
    print("Action:", step["action"])
    print("Observation:", step["observation"])
print(result["answer"])
```

最终答案应为 `Calculation result: 1152. Shanghai is in China.`。最后的 `finish` 记录没有工具观察，因为它不调用外部工具。

## 4. 为什么必须设置 max_steps

工具可能失败，planner 也可能反复选择同一个动作。`max_steps` 是循环的硬性安全边界：达到上限后返回 `stop_reason="max_steps"`，不再继续调用工具。

未知问题会走安全结束分支；已知工具收到不支持的输入时，会返回 `ok=False`，循环以 `tool_error` 停止。这样可以防止玩具 Agent 在无法完成任务时无限循环。

## 5. 真实 LLM Agent 也是这个循环

真实 LLM Agent 的核心外层循环同样是 Thought → Action → Observation，只是 planner 通常换成模型：模型根据目标、工具说明和已有观察生成下一步动作。外层代码仍负责执行工具、记录结果、限制步数，并在失败或超时时停止。

本章用确定性规则替换模型，是为了让每条 trace 都可复现、可测试，并把 Agent 的控制流与模型能力分开理解。规则 planner 不意味着真实 Agent 只能使用规则。
