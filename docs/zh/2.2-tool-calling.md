# 2.2 工具调用：从计划到受控的本地执行

## 1. 这一章要解决什么

通过结构验证的计划仍然不是执行许可。本章连接“模型给出计划”和“程序执行工具”两个阶段，并保证只有注册、获准且参数正确的工具才能运行。

示例只有两个本地工具：`calculator` 计算算术表达式，`lookup_city` 查询固定城市表。整个过程纯 CPU，无网络、GPU 或付费 API。

## 2. 注册表与安全计算器

`TOOL_REGISTRY` 保存工具处理器及参数类型。`ALLOWED_TOOLS` 是默认白名单；调用方可以传入更小的集合，但不能借此运行注册表之外的工具。

计算器不使用 `eval()`。它把表达式解析为 AST，只接受数字、正负号以及 `+`、`-`、`*`、`/`、`//`、`%`。函数调用、名字引用和其他语法都会被拒绝。`lookup_city` 只读取本章内置的三个城市，不访问外部服务。

## 3. 执行一个结构化计划

在仓库根目录执行：

```bash
uv run python chapters/stage2-agent-core/tool_calling.py
```

`run_minimal_path()` 解析计划 `(6 + 2) * 7`，调用计算器，并返回 `chapter`、`tool`、`arguments` 和 `result`。结果是整数 `56`，重复运行完全一致。

## 4. 执行前的四道检查

`execute_plan()` 先调用 `parse_plan()` 检查三个计划字段及置信度范围，然后进入 `call_tool()`：

1. 工具必须存在于注册表。
2. 工具必须位于本次调用的白名单。
3. 参数必须齐全、没有多余字段且类型正确。
4. 处理器自身还要检查表达式或城市是否有效。

任何一步不通过都会抛出 `ValueError`，不会静默忽略错误，也不会退回去执行另一个工具。

## 5. 亲手限制工具权限

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/tool_calling.py")
plan = {"action": "calculator", "arguments": {"expression": "2 + 3 * 4"}, "confidence": 0.9}
print(chapter["parse_plan"](plan))
print(chapter["execute_plan"](plan))
try:
    chapter["execute_plan"](plan, allowed_tools={"lookup_city"})
except ValueError as exc:
    print(exc)
```

前两次输出分别显示规范化后的计划和结果 `14`；最后一次输出白名单拒绝信息。冒烟测试还会检查未知工具、参数错误和执行的确定性。
