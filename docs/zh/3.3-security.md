# 3.3 安全基础：提示注入扫描与工具白名单

## 1. 这一章要解决什么

Agent 会把网页、文档和用户输入交给模型，也可能根据模型输出调用工具。攻击者可以在这些文本中夹带指令，例如要求模型忽略原规则、泄露系统提示或调用未授权工具。这就是提示注入需要应对的一类风险。

本章实现一个纯标准库的教学扫描器和一个默认拒绝的工具白名单。它们能展示基本思路，但不是完整安全方案，也不能保证阻止所有攻击。

## 2. 规则扫描与白名单怎样协作

`PromptInjectionScanner` 先做 Unicode NFKC 规范化、大小写折叠和空白合并，再按固定顺序匹配三组规则：忽略先前指令、泄露系统提示、调用未授权工具。返回的 `risk_level` 为 `low` 或 `high`，`matched_rules` 记录命中的规则编号。

`ToolPolicy` 保存允许的工具名，采用精确、大小写敏感的匹配。工具不在白名单中时默认拒绝。`evaluate_request()` 同时检查提示和工具，只有两者都允许才返回 `allow`。

规则扫描只能发现已知或相似模式：它可能漏掉改写、编码、多语言混合等攻击，也可能误伤正常讨论安全话题的文本。因此扫描结果应作为风险信号，而不是安全证明。

## 3. 运行安全实验

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage3-reliability/security.py
```

输出对比一个正常的文档搜索请求和一个恶意请求。正常请求的风险低且放行；恶意请求命中三组规则，并且请求的 `shell` 工具不在白名单中，因此最终拒绝。

## 4. 检查每一步决策

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage3-reliability/security.py")
result = chapter["run_minimal_path"]()
for name in ("normal_request", "malicious_request"):
    item = result[name]
    print(name, item["risk_level"], item["matched_rules"], item["decision"])
```

冒烟测试覆盖正常请求放行、三类注入模式、白名单外工具拒绝、大小写与空白变形，以及重复运行结果一致。注意，白名单工具本身仍可能被危险参数滥用。

## 5. 建立分层防御

不能把安全交给一条正则表达式。实际系统还应做到：

- 权限最小化：按任务授予最少工具、最小数据范围和最短有效时间，默认拒绝。
- 人工确认：删除文件、发送消息、修改账户等高风险操作必须由人确认，并展示具体参数。
- 隔离执行：使用独立进程、容器或低权限账号，限制网络、文件系统和资源，避免直接访问宿主机凭据。
- 数据与审计：把不可信内容标记为数据，清理敏感信息，记录工具调用和拒绝原因，并限制日志访问。
- 持续评估：用攻击样本和正常样本测试漏报、误报；规则变化后重新验证，不把一次通过当作永久安全。

这些层共同降低风险。任何单层失效时，其他层仍应限制损害。
