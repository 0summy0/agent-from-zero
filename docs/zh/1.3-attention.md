# 1.3 上下文窗口与注意力：从点积到加权混合

## 1. 这一章要解决什么

模型处理一个 token 时，怎样知道当前窗口里哪些 token 更值得参考？本章用 5 个手工向量，逐步实现一个极小的 scaled dot-product attention（缩放点积注意力）。只用 Python 标准库和 CPU，不需要 GPU、网络、模型权重或 API key。

示例中的 `I like small models too` 只是便于观察的 toy token，不代表对自然语言的完整建模。每个 token 都有 query、key、value 三个二维向量。

## 2. query、key、value 分别做什么

可以把一次注意力计算想象成“提问—匹配—取内容”：

- query 是当前 token 的问题：我正在寻找什么信息？
- key 是候选 token 的索引：我这条信息适合回答哪些问题？
- value 是候选 token 的内容：匹配成功后，我能贡献什么信息？

当前 query 与每个 key 做点积，分数越高，表示匹配越强。softmax 把分数变成总和为 1 的注意力权重；再用这些权重对 value 加权求和，得到当前 token 的 context vector（上下文向量）。

```text
score_j = dot(query, key_j) / sqrt(d_k)
weight_j = exp(score_j) / sum(exp(scores))
context = sum(weight_j * value_j)
```

这里 `d_k` 是 key 向量的维度。本例中每一维的数值都很小，缩放不会让权重变得极端；缩放的意义要在更高维、更大数值时更容易观察。

## 3. 为什么要除以根号 d_k

点积会把各维的乘积相加。假设各维近似独立且方差为 1，向量维度为 `d_k` 时，点积的方差也约为 `d_k`。随着维度增大，分数可能变得过大，softmax 会迅速集中到少数候选，梯度也会变小。

除以 `sqrt(d_k)` 是为了让分数尺度更稳定。它不会改变点积的大小顺序，也不会把 softmax 权重变成总和为零的分数。

代码先减去最大分数再计算指数：`exp(score - max)`。这是数值稳定技巧，不改变最终的 softmax 结果，却能避免 `exp` 溢出。

## 4. 运行完整示例

在仓库根目录执行：

```bash
uv run python chapters/stage1-how-lm-works/attention.py
```

输出分为 `full_window` 和 `context_window` 两部分。前半部分保留全部 5 个 token；后半部分只保留最近 3 个。每一行依次展示 query token、缩放点积分数、attention weights 和 context vector，`keys` 与 `values` 则列出本次窗口里被检索和混合的内容。

完整的输出结构可以直接用标准库检查：

```python
import runpy

chapter = runpy.run_path("chapters/stage1-how-lm-works/attention.py")
result = chapter["run_minimal_path"]()
for row in result["context_window"]["rows"]:
    print(row["query_token"], sum(row["attention_weights"]))
    print(row["context_vector"])
```

每个权重行的和应约为 1，context vector 的维度应等于 value 向量的维度。代码使用固定玩具数据，没有随机过程，所以重复运行得到相同结果。

## 5. 超出窗口时保留最近 N 个 token

```python
import runpy

chapter = runpy.run_path("chapters/stage1-how-lm-works/attention.py")
print(chapter["truncate_to_recent_tokens"](["a", "b", "c", "d", "e"], 3))
print(chapter["run_minimal_path"]()["context_window"]["kept_tokens"])
```

第一行输出 `['c', 'd', 'e']`，第二行输出 `['small', 'models', 'too']`。截断发生在计算注意力之前，因此被丢弃的 token 不会出现在 keys、values 或权重中。

本例采用单头、无掩码的全窗口注意力：窗口内每个 query 都能看到所有 key。真实生成式模型通常还会加入因果掩码，阻止当前位置看到未来 token，并使用可学习投影和多头注意力。这里的 `demo_scope` 字段明确记录了这些简化，避免把玩具计算误当成完整模型。

## 6. 上下文窗口不是“记忆”本身

上下文窗口是模型一次前向计算能够接收的 token 容量。窗口变大不等于模型自动记住或理解所有内容；窗口内的信息仍要经过注意力读取，窗口外的 token 在本步输入中也不可见。

模型参数可以看作训练后保存的长期能力，而当前上下文窗口是本次推理的临时工作区。两者不是同一个概念。本例的“保留最近 N 个”只是演示一种截断策略，并不声称它适合所有任务；重要指令、检索结果或长文档可能需要其他管理和摘要方法。
