# 1.4 幻觉：模型为什么会编造答案

## 1. 这一章要解决什么

语言模型有时会给出听起来合理、实际上没有依据的答案，这叫幻觉。本章不用模型权重或在线服务，而是搭建一个最小的“有证据才回答”机制：先检索本地知识库，再决定回答还是弃权。

全程只使用 Python 标准库，不需要网络、GPU 或 API key。玩具知识库故意很小，目的是看清控制流程，而不是展示知识问答效果。

## 2. 幻觉不是说谎

“说谎”意味着说话者知道事实却故意欺骗；幻觉通常没有这个意图。语言模型的核心能力是根据上下文生成合理的后续文本。训练中学到的语言模式、事实关联和推理习惯混在一起，当证据缺失、问题模糊或上下文冲突时，一个通顺的猜测也可能被生成出来。

因此，降低温度、让语气更肯定，或者把回答写得更详细，都不能证明答案正确。第 1.2 章的采样改变的是“选哪个 token”，不会自动补上事实依据。

## 3. 有证据才回答的最小机制

本章把回答拆成三个步骤：

1. **检索**：把问题转成小写关键词，去掉 `what`、`is`、`the` 等功能词；在每条证据的标题、别名和正文中查找。
2. **证据门控**：只有同一条证据覆盖问题的全部有效关键词，才允许回答。优先选择标题或别名命中更多的证据。
3. **回答或弃权**：有证据时直接引用正文并附上证据 ID；没有证据时返回“不知道，需要更多信息”，不补写猜测。

`answer_with_evidence(question, knowledge_base)` 返回 `status`、`answer`、`evidence` 和 `query_keywords`。`status` 为 `grounded` 时表示走了证据回答路径，为 `abstain` 时表示弃权。

这个门控故意保守。例如，“法国和加拿大的首都是什么”需要两条证据，本章不会把两条孤立事实拼成一个答案，而是弃权。关键词覆盖也不等于逻辑蕴含：它不会处理否定、复杂比较或同义改写。真实系统还需要更可靠的检索、证据校验和受约束生成。

## 4. 跑通对照实验

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage1-how-lm-works/hallucination.py
```

最小路径对比两个问题：知识库内的法国首都问题会返回 `Paris is the capital of France.` 和证据 `kb-capital-france`；知识库外的亚特兰蒂斯首都问题会返回弃权，因为没有任何本地证据覆盖 `atlantis`。

这里的 grounded answer 直接摘自证据，而不是自由生成。这样可以把“检索是否找到依据”和“如何组织语言”分开观察。

## 5. 亲手检查结果

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage1-how-lm-works/hallucination.py")
result = chapter["run_minimal_path"]()
print(result["grounded_case"]["status"])
print(result["grounded_case"]["answer"])
print(result["abstention_case"]["status"])
print(result["abstention_case"]["answer"])
```

可以看到，有证据时输出 `grounded` 和带 ID 的引用；无证据时输出 `abstain` 和明确的不知道。冒烟测试还会检查证据 ID 非空、组合问题不会错误拼接答案，以及重复运行结果完全一致。

## 6. 边界、自测与下一步

检索证据、引用和弃权是工程缓解手段，不是彻底消除幻觉。知识库可能过期或不完整，检索可能漏掉证据，生成器也可能忽略证据。要获得更强保证，还需要评估引用是否真正支持断言，并为高风险场景设置人工复核。

打开 `quizzes/1.4-hallucination.json` 完成三道中文自测题；英文题集在 `quizzes/1.4-hallucination.en.json`。

下一步可以给 `KNOWLEDGE_BASE` 添加一条证据和问题，观察关键词门控；也可以尝试问一个缺少关键事实的问题，确认系统选择弃权而不是补全答案。
