# 4.4 毕业项目：Local Research Desk 本地研究台

## 1. 这个项目要解决什么

Local Research Desk（本地研究台）把前几章的机制组合成一条可运行、可检查的研究流程：接收问题，扫描注入请求，生成结构化计划，执行本地工具，引用证据，最后回答或弃权。它只使用 Python 标准库和仓库已有的 `jsonschema`，在 CPU 上运行，不需要网络、GPU、模型权重或付费 API。

**这是教学毕业项目，不是生产系统。** 规划器使用固定规则而不是 LLM，知识库只有少量手工事实，检索使用关键词覆盖。它用于理解 Agent 的控制流与可靠性边界，不提供开放领域研究能力。

## 2. 一条流水线，多种可靠性机制

一次 `run(question)` 依次经过以下阶段：

1. **输入检查与安全扫描**：限制问题长度，做 Unicode NFKC 规范化，匹配已知提示注入模式。命中后直接拒绝，不执行工具。
2. **任务识别**：固定规则识别算术、城市查询和知识库问题，并生成 `action`、`arguments`、`confidence` 计划。
3. **Schema 验证**：每个计划都通过 `PLAN_SCHEMA`；工具参数、动作名称、额外字段和最终证据 ID 数量都受到约束。
4. **有界 ReAct 循环**：按 Thought → Action → Observation 执行，最多 4 步，包含最后的 `finish`。
5. **证据门控与回答**：知识回答直接引用本地记录；计算结果和城市记录也成为可引用观察。没有支持证据时返回 `abstain`。
6. **记忆、追踪与评测**：维护最近消息窗口和旧消息摘要，写 JSONL trace，并返回 token 估算、工具调用数和简单指标。

返回结果包含 `answer`、`status`、`evidence`、`trace`、`usage`、`evaluation`、`memory`、`security`、`plan_validation` 和 `trace_file`。所有值都可以用 `json.dumps(..., allow_nan=False)` 序列化。

## 3. 运行 demo 与单个问题

在仓库根目录执行：

```bash
uv run python -m agent_from_zero.capstone --demo
```

demo 运行两个固定问题：法国首都在知识库内，状态为 `grounded`；亚特兰蒂斯首都没有本地证据，状态为 `abstain`。输出顶层的 `statuses` 是 `["grounded", "abstain"]`，两个完整结果分别位于 `cases.grounded` 和 `cases.abstain`。

只研究一个问题：

```bash
uv run python -m agent_from_zero.capstone "What is the capital of France?"
```

也可以把 trace 写入自己指定的目录：

```bash
uv run python -m agent_from_zero.capstone "Calculate (6 + 2) * 7" --trace-dir traces/research
```

这会在 `traces/research/trace.jsonl` 写入逐行 JSON。不指定 `--trace-dir` 时，每次运行创建独立的临时目录；返回结果只标记 `temporary: true`，不暴露随机路径，因此默认结果仍可确定复现。demo 使用指定目录时，会在其 `grounded` 和 `abstain` 子目录分别写文件。

## 4. 检查有证据回答与弃权

grounded 结果直接摘自证据，并在方括号中附上 ID：

```text
Paris is the capital of France. [kb-capital-france]
```

无证据结果不会补写一个看似合理的首都，而是明确弃权：

```text
I don't know; no verifiable local evidence is available for this question.
```

`retrieve_knowledge()` 要求同一条记录覆盖问题的全部有效关键词。因此，“法国和加拿大的首都”不会把两条孤立事实拼成答案。这个规则故意保守：它不理解否定、复杂比较或所有同义改写，关键词覆盖也不等于逻辑蕴含。

## 5. 结构化计划与四步 ReAct 循环

`calculator`、`lookup_city` 和 `search_knowledge` 是仅有的三个本地工具。计划必须先通过 JSON Schema，再进入 `execute_action()`。例如，布尔值不能冒充置信度，未知动作、多余参数和无证据的 `grounded` 最终计划都会被拒绝。

循环最多执行 4 步。一个“先计算，再查上海”的问题会依次选择 `calculator`、`lookup_city`、`finish`；工具失败时进入弃权分支，不会反复重试。安全拒绝发生在规划之前，只记录一条 `reject` 观察。

下面的代码可以直接检查计划与 trace：

```python
import json
from agent_from_zero.capstone import run, validate_plan

result = run("Calculate (128 + 256) * 3, then look up the country of Shanghai.")
for step in result["trace"]:
    print(step["step"], step["thought"])
    print(step["action"]["action"], step["action"]["arguments"])
print(result["answer"])
print(json.dumps(result["evaluation"], sort_keys=True))

plan = {"action": "calculator", "arguments": {"expression": "2 + 2"}, "confidence": 0.9}
print(validate_plan(plan))
```

最终答案应包含 `1152`、上海所在国家 `China` 和两个引用。规则 planner 只依赖问题与已有观察，不使用随机采样，所以相同输入产生相同 trace 和答案。

## 6. 记忆、上下文与 JSONL trace

`ContextMemory` 最多保留 4 条最近消息，滑出窗口的内容会进入有损摘要，完整上下文再按 640 个字符裁剪。`memory` 字段报告摘要、最近消息、淘汰数量、上下文字符数和估算 token 数。

当前项目没有模型，因此不会把摘要当成新事实；摘要用于展示上下文组织方式。最终回答只根据已验证的工具观察和证据记录。真实系统若使用模型，还必须检查摘要是否丢失约束或引入错误。

每个 ReAct 步骤和最终结果各写一行 JSONL。可以这样读取用户指定目录中的 trace：

```python
import json
from pathlib import Path
from agent_from_zero.capstone import run

result = run("What is the capital of France?", trace_dir="traces/research")
path = Path(result["trace_file"]["directory"]) / result["trace_file"]["name"]
records = [json.loads(line) for line in path.read_text(encoding="utf-8").splitlines()]
print(result["trace_file"]["event_count"])
print([record["event"] for record in records])
print(records[-1]["evidence_ids"])
```

输出依次是步骤数加一、`['step', 'step', 'result']` 和 `['kb-capital-france']`。trace 不包含真实耗时或随机时间戳，便于复现；生产追踪通常还需要关联 ID、时间、采样、保留期限和访问控制。

## 7. 安全计算、注入扫描与评测指标

计算器把表达式解析为 AST，只接受有限数字、括号、一元正负号和 `+`、`-`、`*`、`/`、`//`、`%`。它拒绝函数调用、名字、属性访问、幂运算、超大数字和非有限结果，且从不使用 `eval()` 或 `exec()`。

注入扫描器只覆盖少量已知模式，例如忽略先前指令、泄露系统提示和调用未授权工具。它可能漏报改写或编码攻击，也可能误报正常讨论，因此不是完整安全边界。本项目也没有文件删除、shell、网络或付费工具。

`usage` 中的 token 数是“归一化字符数除以四”的教学估算，不是任何真实 tokenizer 的计数；`network_calls` 和 `cost_usd` 都为零。`evaluation` 报告任务是否成功、是否弃权、注入是否阻断、证据数、引用覆盖率、引用是否出现在答案中、步数和是否遵守上限。这些是小型诊断指标，不等于事实正确性的完整证明。
