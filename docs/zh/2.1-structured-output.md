# 2.1 结构化输出：用 JSON Schema 验证工具计划

## 1. 这一章要解决什么

模型可以生成看起来像工具调用的文本，但“能解析”不等于“能执行”。本章把工具计划限制为一个 JSON 对象：`action` 选择工具，`arguments` 提供参数，`confidence` 表示置信度。

目标是先验证结构和类型，再决定是否进入执行阶段。示例只在本地运行，不需要 GPU、网络或 API key。

## 2. 用 Schema 明确契约

`TOOL_PLAN_SCHEMA` 要求三个字段同时存在：`action` 是非空字符串，`arguments` 是对象，`confidence` 是 0 到 1 之间的数字。`additionalProperties: false` 拒绝多余字段，避免拼写错误悄悄混入计划。

`validate_plan(plan)` 返回 `(valid, errors)`。`valid` 是布尔值，`errors` 是可以直接展示或记录的字符串列表；合法计划的错误列表为空。

## 3. 对比合法与非法计划

在仓库根目录执行：

```bash
uv run python chapters/stage2-agent-core/structured_output.py
```

`run_minimal_path()` 对比两份计划。合法计划包含全部字段，因此 `valid` 为 `true`；非法计划缺少 `confidence`，因此 `valid` 为 `false`，错误中会指出缺失的字段。返回值全部由可 JSON 序列化的值组成。

## 4. 修复传输层，不猜测业务内容

模型有时把 JSON 包在 Markdown 代码围栏里。`repair_json(text)` 可以提取一个 `json` 围栏中的内容，也可以直接解析普通 JSON 文本。它拒绝非法 JSON、非对象 JSON 和多个 JSON 围栏。

这个函数只修复外层包装，不会补全缺失字段，也不会把错误类型强行转换。提取后仍应调用 `validate_plan()`；Schema 验证与 JSON 解析是两道独立检查。

## 5. 亲手检查结果

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/structured_output.py")
plan = {"action": "calculator", "arguments": {"expression": "2 + 2"}, "confidence": 0.9}
print(chapter["validate_plan"](plan))
fenced = (
    '```json\n{"action": "lookup_city", "arguments": {"city": "Beijing"}, "confidence": 0.8}\n```'
)
print(chapter["repair_json"](fenced))
print(chapter["run_minimal_path"]())
```

冒烟测试覆盖合法计划、缺字段、类型错误、围栏提取和非法 JSON。可以试着把 `confidence` 改成字符串，观察错误如何变化。
