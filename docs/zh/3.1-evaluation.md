# 3.1 评测：用一个小型评测集衡量回答质量

## 1. 这一章要解决什么

Agent 能回答一个问题，不代表它可靠。评测把“看起来不错”变成可重复的检查：固定输入、期望答案和判定规则，然后统计有多少回答通过。

本章使用四道纯文本 toy 题，不调用模型或外部服务。重点是评测流程，而不是题目本身的难度。

## 2. 三种基础检查

`normalize_text()` 先做大小写归一化并合并多余空白。`exact_match()` 要求归一化后的回答等于期望答案或某个允许别名，因此 `PARIS`、`Paris` 和 ` four ` 都可以按规则接受。

`contains_expected()` 只检查期望答案是否出现在回答中。它更宽松，能接受“答案是 Paris”，但也可能误判包含目标词的错误句子，适合作为单独的诊断信号。

`evaluate()` 接收评测集和逐题回答，返回总数、通过数、通过率以及逐题结果。空评测集会报错，避免产生没有意义的通过率。

## 3. 跑通最小评测

在仓库根目录执行：

```bash
uv run python chapters/stage3-reliability/evaluation.py
```

四道题中 `paris` 因大小写归一化通过，`SEVEN` 因别名 `seven` 通过，`blue` 失败，所以 `pass_rate` 是 0.75。逐题 `results` 会保留预测答案，方便定位失败来源。

## 4. 准确率不是全部

准确率或通过率回答的是“有多少题达到预设标准”，但上线决策至少还要看以下指标：

- 任务成功率：多步任务是否真正完成目标，而不只是最终文本匹配。
- 证据引用：结论是否有可靠依据，引用是否支持结论且可以核查。
- 延迟：用户需要等待多久，尾延迟是否可接受。
- 成本：单次任务和批量评测消耗多少 token、工具额度或费用。

此外还应检查失败类型、不同难度和语言上的表现、异常率与安全性。一个总体准确率可能掩盖少数关键场景中的严重失败。

## 5. 亲手检查结果

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage3-reliability/evaluation.py")
print(chapter["run_minimal_path"]()["pass_rate"])
print(chapter["contains_expected"]("The answer is PARIS.", "paris"))
report = chapter["evaluate"](chapter["EVALUATION_SET"], ["4", "Paris", "green", "7"])
print(report["passed"])
```

冒烟测试覆盖精确匹配、别名、大小写归一化、失败案例、空数据集报错、答案数量校验和确定性。修改 toy 回答后，可以通过逐题结果判断是规则问题还是回答问题。
