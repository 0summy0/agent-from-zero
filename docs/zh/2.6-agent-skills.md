# 2.6 Agent Skills：发现、按需加载与提示词渲染

## 1. 这一章要解决什么

当 Agent 拥有很多工作说明时，把所有 `SKILL.md` 原文一次性塞进上下文既浪费空间，也容易让模型分心。技能机制把“发现元数据”和“加载完整指令”分成两步：先看有哪些技能，再只载入当前任务需要的一个。

本章实现一个纯标准库、CPU 本地运行的 `SkillLibrary`。它不调用模型，不需要网络、GPU 或 API key，也不执行技能文件中的任何代码。技能只是可注入提示词的 Markdown 指令。

## 2. 约定的目录与 front matter

`SkillLibrary(root)` 只扫描 `root/skills/*/SKILL.md`，即 `skills` 下每个直接子目录中的一个文件。每个文件采用如下结构：

```markdown
---
name: summarize
description: "Condense a passage into three factual bullet points."
---

Read the passage. Preserve named entities and numbers.
Return exactly three bullets.
```

开头的 YAML 风格 front matter 必须提供非空的 `name` 和 `description`；结束分隔线之后的正文成为 `instructions`。本章的解析器是教学子集：支持单引号或双引号包裹的单行标量，不支持完整 YAML、列表、嵌套对象或多行块。重复名称或缺少必要字段会报错，避免发现阶段产生歧义。

`list_skills()` 按名称排序，只返回名称和描述，不返回正文。这种元数据视图让 Agent 能先做选择，而不必支付加载全部指令的上下文成本。

## 3. 先发现，再按需加载

`load_skill(name)` 在已发现的文件中查找指定名称，返回包含 `name`、`description` 和 `instructions` 的字典；找不到时抛出 `KeyError`。`render_skill_prompt(skill)` 接收一个已经加载的字典，把描述与指令组织成稳定的 Markdown 片段。

渲染函数不会遍历技能库，也不会自动加载其他技能。因此，未加载技能的正文不会进入 prompt。重复调用相同输入会得到相同文本，目录扫描顺序和最终技能列表也保持确定。

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage2-agent-core/skills.py
```

演示用 `tempfile.TemporaryDirectory` 创建 `summarize` 与 `translate` 两个技能，发现两者后只加载 `summarize`。返回的 `discovered_skills` 包含两个元数据条目，而 `prompt` 只包含 `summarize` 的指令。临时目录会自动清理，输出不包含随机路径。

## 4. 检查发现与加载的区别

把下面代码交给 `uv run python -` 执行：

```python
import runpy

chapter = runpy.run_path("chapters/stage2-agent-core/skills.py")
result = chapter["run_minimal_path"]()
print([skill["name"] for skill in result["discovered_skills"]])
print(result["skill_name"])
print(result["instructions"])
print("translate" in result["prompt"])
```

最后一行应输出 `False`。这说明“发现一个技能”不等于“把它的指令注入当前任务”。冒烟测试还会检查两个技能的发现、指定技能加载、缺失技能报错、未加载技能不进入 prompt，以及结果的确定性和 JSON 可序列化性。

## 5. 安全与工程边界

技能文本可能来自外部仓库，应视为不可信输入。本章只读取和渲染文本，不导入技能目录中的 Python，不运行 shell 命令，也不把技能说明当作权限授权。实际系统仍需限制工具权限、提示词注入防护和人工确认。

这个加载器也不是完整的 Agent Skills 规范实现：它不支持附属脚本、资源目录、递归发现、YAML 的全部特性或远程技能注册。对于本章，最重要的是渐进式披露——用少量元数据做选择，只在需要时加载完整指令。

## 6. 亲手检查结果

尝试给临时库增加第三个技能，并保持 `name` 唯一。比较增加前后 `list_skills()` 的长度，再只加载其中一个，确认 prompt 不包含另外两个技能的正文。
