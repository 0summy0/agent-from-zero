# 4.2 Browser Use：用本地页面理解浏览智能体

## 1. 这一章要解决什么

当 Agent 需要根据网页内容采取行动时，它必须先观察页面，再决定下一步，最后调用工具执行。本章用一个无网络的本地 `BrowserTool` 演示这个 observe→decide→act 循环。

本章不调用真实浏览器，也不访问互联网。三个 HTML 页面直接保存在内存中，解析与导航只使用 Python 标准库，不需要 GPU、API key 或额外依赖。

## 2. 把网页变成可观察的结构

`parse_html()` 使用 `html.parser.HTMLParser` 提取页面标题、正文可见文本和链接。脚本、样式、`noscript` 与带 `hidden` 属性的内容不会进入正文文本；标题单独保留，链接则记录为“可见文本 + 目标地址”。

这不是完整的浏览器渲染器：它不执行 JavaScript，不理解布局，也不加载图片或外部资源。教学示例故意保持这个小边界，让观察结果确定、可测，并避免把网页内容误当成可执行指令。

## 3. observe→decide→act 循环

1. **Observe（观察）**：`open_page()` 返回 `url`、`title`、`text`、`links`。Agent 从这里了解当前页面，而不是猜测页面内容。
2. **Decide（决定）**：根据任务和观察结果选择动作。本章的目标是阅读文档，因此选择文本为 `Documentation` 的链接。
3. **Act（行动）**：`click_link()` 按完整可见链接文本匹配，随后只打开页面白名单中的本地地址，并返回新页面的观察结果。

行动后要重新观察：标题、正文和链接都可能变化。循环应有步数上限；当目标达成、没有匹配链接或需要用户确认时，应停止而不是反复点击。

## 4. 选择器为什么要稳定

真实网页常出现自动生成的 class、随机 ID、`nth-child` 序号和动态布局。复制这些脆弱选择器，页面稍一改版就会失效。本章采用规范化后的完整可见链接文本，并忽略大小写差异；它不进行子串猜测。

稳定不等于可以盲目点击。同名链接出现多次时，应拒绝执行并报告歧义；未知链接也直接报错。`click_link()` 的匹配要求完整文本一致，目标链接还必须通过本地页面白名单。

## 5. 跑通本地导航

在仓库根目录执行：

```bash
uv sync --frozen
uv run python chapters/stage4-orchestration/browser_use.py
```

输出中的 `title` 是文档页标题，`text_summary` 是规范化正文的前 160 个字符。每次运行都从新的 `BrowserTool` 开始，页面与导航状态互不共享，因此结果可复现。

再用下面的代码检查一次观察与行动：

```python
import runpy

chapter = runpy.run_path("chapters/stage4-orchestration/browser_use.py")
browser = chapter["BrowserTool"]()
home = browser.open_page(chapter["HOME_URL"])
print(home["title"])
print([link["text"] for link in home["links"]])
docs = browser.click_link("Documentation")
print(browser.current_url())
print(docs["title"])
```

冒烟测试覆盖标题与链接提取、按文本点击导航、未知链接拒绝、实例间页面隔离，以及输出确定且可 JSON 序列化。

## 6. 权限、确认与下一步

本地工具只有三个只读页面，没有网络、表单提交或账户操作能力；未知地址和外部链接都会被拒绝。这展示了最小权限：只暴露完成任务所需的动作。

真实浏览器 Agent 需要单独定义权限边界。打开公开页面可以是低风险只读操作；发送消息、下单、修改设置、下载文件和提交包含个人信息的表单，则应在执行前取得用户明确确认，并限制允许的域名、操作类型和参数。Cookie、密码与验证码不能因为页面要求就自动交出。

下一步可以增加一个受控的白名单页面，或给循环加入最大步数；不要直接把本章工具改成 unrestricted 的网络浏览器。完成 `quizzes/4.2-browser-use.json` 的三道自测题；英文题集在 `quizzes/4.2-browser-use.en.json`。
